# explain v1 검증 질문

공개 사본 안내: 원래 기본 질문 목록에서 링크만 공개 묶음에 맞췄고, 아래에 실제 추가 시험의 구분을 덧붙였다. 질문 목록을 실행 결과로 보지 않는다.

2026-10-13 Claude T02-table의 실제 입력에는 명시 호출과 Markdown 표 요청이 추가됐다. [v1 입력](evidence/v1/T02-table/input.txt)과 [c01 입력](evidence/c01/T02-table/input.txt)은 서로 같은 바이트다. T03의 실제 입력도 [v1](evidence/v1/T03/input.txt)과 [c01](evidence/c01/T03/input.txt)이 같다.

해당 실행의 인계서 기준은 T02에서 전체/개인별 용량 단정과 조건 없는 비용 분담을 금지했고, T03에서 필요조건을 충분조건으로 강화하지 않도록 명시했다. c01도 같은 의미 기준으로 응답 전체를 판정했다. T08의 전체 중단/개별 중단 및 재시도 배치는 원문에 미정이면 가정으로 구분한다. T10-A의 짧은 완료 상태 안내는 허용하며 관찰 로그상의 호출 징후 부재와 내부 절대 비선택은 구분한다.

아래는 실행할 질문과 판정 기준이다. **질문 목록 자체는 실행 결과가 아니다.** 실제 실행 상태와 근거는 [공개 검증 요약](README.md)에 따로 남긴다. 사례의 서비스·장치·자료는 모두 검증용 가정이다.

## 실행 방법

- 설치와 호출은 [README](../README.md)를 따른다. 제품·버전·모델·날짜·설치 범위와 실제 답변을 기록한다.
- 명시 호출은 Codex에서 질문 앞에 `$explain`, Claude Code에서는 `/explain`을 붙인다. 본문을 프롬프트에 붙여 넣은 것만으로 정식 스킬 탐색·로딩이 검증되었다고 하지 않는다. 실행 기록에서 본문 로딩 근거도 확인한다.
- T01은 명시 호출과 이름을 붙이지 않은 자동 선택을 각각 확인한다. T10은 이름 없이 수행한다. 나머지는 명시 호출을 기본으로 한다.
- 비교할 수 있으면 같은 모델·설정의 새 세션에서 같은 질문을 스킬 없이, 그리고 스킬을 켜고 각각 실행한다. 미적용 세션에서는 자동 선택도 막아야 한다. 다른 스킬이나 사용자 지침의 영향을 기록한다.
- 각 사례를 통과·실패·미검증으로 판정한다. 원문 의미 손실, 사용자 형식 위반, 무관한 작업을 설명으로 대체한 경우는 실패다. 표현 취향이나 답변 길이만으로 우열을 정하지 않는다.
- 한 번의 답변으로 이해 시간 단축이나 안정적인 자동 호출을 입증하지 않는다. 실행이 막힌 환경은 사유와 함께 미검증으로 남긴다.

## T01 — 단순 질문과 과잉 생성

**질문:** `컴퓨터를 잘 모르는 사람에게 캐시가 무엇인지 쉽게 설명해줘.`

**기준:** 재사용을 위해 데이터나 결과를 보관한다는 핵심이 먼저 나온다. 전문 용어를 불필요하게 늘리지 않는다. 글로 충분한 질문에 파일·표·그림·HTML을 만들지 않는다. 자동 선택 시험에서는 실제 explain 로딩 여부를 별도로 기록한다.

## T02 — 비교 표

**질문:** `가상 상품 A는 월 5,000원, 1명, 10GB, 오프라인 미지원이고, B는 월 9,000원, 최대 3명, 30GB, 오프라인 열람만 가능해. 둘 다 용량 초과 시 새 업로드만 차단돼. 차이를 비교해줘.`

**기준:** 같은 기준으로 비교한 표가 유용하다. 가격·인원 상한·단위와 공통 제한을 유지한다. B가 오프라인 편집까지 지원한다고 쓰거나 기존 파일 열람도 차단된다고 쓰면 실패다. 근거 없이 우승 상품을 고르지 않는다.

## T03 — 부정·경계값·단위·예외

**질문:** `이 가상 장치 안내를 쉽게 풀어줘. "온도가 80°C 이상일 때만 자동 정지가 작동한다. 단, 점검 모드에서는 자동 정지가 작동하지 않는다. 정지 후 최소 10분 동안 전원을 다시 켜지 말아야 한다."`

**기준:** 80°C를 포함하는 경계, 그 조건에서만 작동한다는 제한, 점검 모드 예외, 정지 후 최소 10분간 재가동 금지가 모두 남는다. 80°C 초과로 바꾸거나 10분 후 안전이 보장된다고 추가하면 실패다.

## T04 — 정적 다이어그램과 의미 있는 화살표

**질문:** `Mermaid를 표시할 수 있어. 가상 신청 절차를 작은 Mermaid 도식과 짧은 설명으로 보여줘. 접수 후 항목을 확인해. 누락이면 보완 요청을 하고, 보완되면 항목을 다시 확인해. 누락이 없으면 심사하고 통과 시 승인, 미통과 시 반려해. 접수만으로 승인이 보장되지는 않아.`

**기준:** 보완→재확인 반복, 누락 분기, 심사 결과가 보존된다. 화살표는 절차 순서로 읽힌다. 설명만 읽어도 핵심을 안다. Mermaid 소스 작성과 실제 렌더링 성공을 각각 기록한다. 렌더링을 못 했다면 그 부분만 미검증이다.

## T05 — 그림을 못 보는 환경

**질문:** `그림과 Mermaid를 표시할 수 없는 터미널이야. 수신한 메시지를 대기열에 넣고, 작업자가 하나씩 처리한 뒤 성공 결과를 저장해. 처리에 실패한 메시지는 재시도 대기열로 보내. 이 흐름을 설명해줘.`

**기준:** 글·단계 목록·텍스트 도식으로 설명한다. 성공과 실패 경로를 보존하고 재시도 횟수나 성공 보장을 지어내지 않는다. 이미지 링크나 Mermaid 렌더러에만 의존하거나 설치를 요구하면 실패다.

## T06 — 사용자 언어와 정확한 출력 형식

**질문:** `캐시가 무엇인지 설명해줘. 영어로 답하고 {"explanation":"..."} 형태의 JSON 객체만 반환해. explanation 값은 쉬운 영어 두 문장으로 써줘. 코드 블록이나 표, 비유는 쓰지 마.`

**기준:** JSON으로 파싱되며 키는 explanation 하나다. 값은 영어 두 문장이고 핵심 의미가 맞다. 한국어 기본값, 머리말, 코드 펜스, 그림, 비유를 덧붙이면 실패다. 스킬 안내도 JSON 밖에 쓰지 않는다.

## T07 — 상관관계와 불확실성

**질문:** `다음 가상 관찰 자료를 쉽게 설명해줘. "한 달 동안 관찰한 200명에서 앱을 자주 쓴 집단의 평균 점수가 더 높았다. 무작위 배정은 없었고 사전 점수도 측정하지 않았다. 앱 사용이 점수를 높였는지는 알 수 없다."`

**기준:** 기간·표본 수·집단 평균 비교·연구 제약을 유지한다. 앱이 점수를 올린다고 단정하지 않는다. 증가 폭이나 통계적 유의성을 만들어내지 않는다. 인과 화살표를 그리지 않는다.

## T08 — 비유와 깊이 조절

**질문:** `비전공자에게 가상의 "작업 대기열"을 식당 주문에 비유해서 자세히 설명해줘. 이 시스템은 접수 순서대로 작업을 하나씩 처리하고, 실패한 작업은 딱 한 번만 다시 시도한 뒤 또 실패하면 중단해. 비유와 실제 규칙을 구분해줘.`

**기준:** 요청에 맞게 충분히 설명한다. 접수 순서·순차 처리·재시도 1회·두 번째 실패 후 중단을 유지한다. 식당 비유가 실제 시스템의 증거나 무한 재시도 규칙이 되지 않는다. 임의의 짧은 답변 제한 때문에 핵심을 생략하지 않는다.

## T09 — HTML·영상 지원 경계

다음 두 질문을 별도 새 세션에서 시험한다.

- **A:** `버튼을 누르면 가상 대기열에 작업이 추가되고 처리 과정을 볼 수 있는 인터랙티브 HTML을 만들어줘.`
- **B:** `가상 대기열의 처리 흐름을 보여주는 20초 설명 영상을 만들어줘.`

**기준:** explain v1 자체는 해당 제작 기능을 지원하지 않는다고 짧게 구분한다. 실행 환경의 일반 기능으로 요청을 수행할 수 있으면 이어가며, 스킬을 이유로 일괄 거부하지 않는다. 수행할 수 없으면 한계를 밝히고 대안을 제시한다. 요청 매체를 말없이 글로 바꾸거나 정적 도식을 영상 완성본이라고 하면 실패다. 외부 전송·설치 등은 해당 환경의 권한을 따른다.

## T10 — 무관한 작업의 자동 호출 억제

명시 호출 없이 다음 두 질문을 각각 시험한다. A는 아래 파일만 있는 임시 작업 폴더에서 실행한다.

- **A:** `calc.py의 add 함수가 합계를 반환하도록 버그를 고쳐줘. 설명은 생략해.`

  ```python
  def add(a, b):
      return a - b
  ```

- **B:** `"Good morning."을 한국어로 번역해줘. 번역문만 출력해.`

**기준:** A는 실제 파일 수정, B는 번역문 출력이라는 목적을 따른다. explain을 자동 선택하거나 설명·표·그림을 추가하지 않는다. 로딩 기록이 없으면 응답 형식만으로 자동 호출 억제까지 검증했다고 하지 않는다.
