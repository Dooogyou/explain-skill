# explain 적용 전후 예시

아래 3개는 **작성자가 만든 설명용 예시**다. 실제 서비스의 정책이나 측정 자료가 아니며, Codex·Claude Code 실행 결과 또는 스킬의 성능 측정 결과가 아니다. 적용 전과 후는 같은 정보를 담되 표현만 바꾼다.

## 1. 글: 수치·조건·불확실성 유지

**요청:** 다음 가상 시험 결과를 비전문가도 이해하도록 풀어줘.

**적용 전**

> 20건의 시험 작업에 대한 평균 처리 시간이 기존 방식의 12분에서 새 방식의 9분으로 감소하였으나, 해당 비교는 파일 크기가 10MB 이하인 작업에 한정되고 전송 실패 건은 제외되었으므로, 새 방식이 모든 작업에서 더 빠르다고 단정할 수는 없다.

**적용 후**

> 이 시험에서는 새 방식의 평균 처리 시간이 기존 방식보다 3분 짧았습니다. 20건의 작업에서 평균이 12분에서 9분으로 줄었습니다.
>
> 다만 파일 크기가 10MB 이하인 작업만 비교했고, 전송에 실패한 작업은 제외했습니다. 따라서 새 방식이 모든 작업에서 더 빠르다고 단정할 수는 없습니다.

**보존 확인:** 20건, 평균값, 12분→9분, 10MB 이하, 전송 실패 제외, 전체 작업으로 일반화할 수 없다는 한계. 3분은 주어진 값의 차이이며 새로운 측정값이 아니다. 비교 대상이 하나라 표나 그림을 추가하지 않았다.

## 2. 표: 같은 기준으로 비교

**요청:** 다음 가상 요금제 A와 B의 차이를 비교해줘.

**적용 전**

> 요금제 A는 월 5,000원에 사용자 1명과 저장 공간 10GB를 제공하지만 오프라인 사용은 지원하지 않는다. 요금제 B는 월 9,000원에 최대 사용자 3명과 저장 공간 30GB를 제공하며 오프라인에서는 열람만 가능하다. 두 요금제 모두 저장 공간을 초과하면 기존 파일 열람은 가능하지만 새 업로드는 차단된다.

**적용 후**

> B는 A보다 월 4,000원 비싸며, 더 많은 사용자와 저장 공간을 제공합니다. 오프라인 열람도 가능합니다.

| 비교 기준 | A | B |
| --- | --- | --- |
| 월 요금 | 5,000원 | 9,000원 |
| 사용자 수 | 1명 | 최대 3명 |
| 저장 공간 | 10GB | 30GB |
| 오프라인 사용 | 지원하지 않음 | 열람만 가능 |

> 두 요금제 모두 저장 공간을 초과하면 새 업로드가 차단됩니다. 기존 파일은 계속 열람할 수 있습니다.

**보존 확인:** 가격·기간·인원 상한·저장 단위가 같다. B의 오프라인 사용을 편집까지 확장하지 않았고, 공통 예외도 남겼다. 어느 요금제가 무조건 더 좋다고 결론 내리지 않았다.

## 3. 정적 도식: 분기와 되돌아가는 경로

**요청:** 다음 가상 신청 절차를 한눈에 이해할 수 있게 보여줘.

**적용 전**

> 신청이 접수되면 필수 항목을 확인하며, 누락이 있는 신청에는 보완을 요청하고 보완된 신청은 다시 필수 항목 확인을 거친다. 누락이 없는 신청만 심사로 넘어가며, 심사에 통과하면 승인되고 통과하지 못하면 반려된다. 접수만으로 승인이 보장되는 것은 아니다.

**적용 후**

> 접수 후 필수 항목을 확인합니다. 누락이 있으면 보완한 뒤 다시 확인합니다. 항목이 모두 있어도 심사에 통과해야 승인됩니다.

```text
접수 -> 필수 항목 확인
          | 누락 있음 -> 보완 요청 -> 보완 -> 필수 항목 확인으로 돌아감
          | 누락 없음 -> 심사
                         | 통과 -> 승인
                         | 미통과 -> 반려
```

> 화살표는 절차의 진행 순서입니다. 접수만으로 승인이 보장되지는 않습니다.

**보존 확인:** 누락 분기, 보완 후 재확인, 심사의 두 결과가 모두 남아 있다. 그림이 렌더링되지 않아도 글과 텍스트 도식으로 핵심 절차를 읽을 수 있다.
